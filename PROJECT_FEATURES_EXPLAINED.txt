1. EXECUTIVE OVERVIEW & SYSTEM ARCHITECTURE
================================================================================
PetConnect is a full-stack monorepo application built with the MERN stack 
(MongoDB, Express.js, React 18, Node.js). It serves as a unified ecosystem for 
pet care, pet adoption, e-commerce, AI pet scanning, and real-time community engagement.

Architecture Overview:
- Monorepo Layout: Dual root folders (/backend and /frontend).
- Domain-Driven Frontend: Frontend components are strictly partitioned by actor 
  in src/modules/{user|caretaker|admin}.
- Bi-directional WebSockets: Integrated Socket.io server attached directly to 
  the Node HTTP server for real-time notifications, typing status, presence 
  tracking, and instant messaging.
- AI Multimodal Pipeline: Integrated with Google Gemini 3.5 Flash Vision API for 
  automated pet scanner analytics.
- Media Pipeline: In-memory Multer file buffer parsing combined with DataURI 
  and Cloudinary v2 API for secure image storage.

2. ROLE-BASED ACCESS CONTROL (RBAC) & AUTHENTICATION
================================================================================
WHAT IT DOES:
Provides secure authentication and user access management across three distinct roles:
1. User (Default): Pet owners looking to buy/sell pets, search caretakers, book 
   services, scan pets with AI, and send connection requests.
2. Caretaker: Verified service providers who showcase professional profiles, 
   set daily/hourly rates, manage service bookings, and interact with pet owners.
3. Admin: Platform moderators with root privileges to approve pet listings, 
   review caretaker applications, approve professional profile drafts, and inspect 
   user accounts.

HOW IT WORKS (TECHNICAL EXECUTION):
- Password Security: Passwords are standardly hashed with bcrypt (salt rounds = 10).
- Session Tokens: Issues JSON Web Tokens (JWT) containing { id, role }. Tokens 
  are transmitted via Authorization: Bearer <token> headers or HTTP-Only cookies 
  (user_token, caretaker_token, admin_token).
- Google OAuth: Integrated using @react-oauth/google on the frontend and 
  google-auth-library on the backend.
- Backend Guard Middleware:
  * isAuth.js: Validates standard user JWTs.
  * caretakerIsAuth.js: Ensures the token holder has role "caretaker".
  * isAdmin.js: Ensures the token holder has role "admin".
  * authenticate.js: Flexible middleware supporting multi-role access checks.
- Frontend Route Protection: Implemented in src/routes/index.jsx via AuthContext.jsx.

3. 🤖 AI PET SCANNER & BREED IDENTIFICATION ENGINE
================================================================================
WHAT IT DOES:
Allows users and visitors to upload or capture any pet image to receive instant, 
deep veterinary and behavioral insights powered by Google Gemini Vision AI.

HOW IT WORKS (TECHNICAL EXECUTION):
- Backend Controller: backend/Controllers/aiController.js powered by @google/generative-ai (gemini-3.5-flash).
- Multimodal Processing: Image buffers parsed via Multer are converted into Base64 
  and sent alongside a strict prompt demanding raw structured JSON output.
- Metrics Extracted:
  * Identification: Primary Breed, Confidence Score (0-100%), Possible Mix.
  * Physical Traits: Estimated Age Stage, Size Category, Weight Range, Grooming Needs.
  * Behavior & Compatibility: Good with Kids, Good with Other Pets, Energy Level, Trainability.
  * Market & Financials: Estimated Price Range in INR, Monthly Maintenance Cost.
  * Health & Care: Breed Health Risks, Dietary Notes, Visual Observations.
  * Fun Fact: Engaging trivia about the identified pet breed.
- Rate-Limiting Architecture (aiRateLimiter.js):
  * Guest Route: POST /api/ai/scan-guest (Rate limited to max 5 requests per 15 min via express-rate-limit).
  * Auth Route: POST /api/ai/scan-auth (Unrestricted AI scanning for logged-in users).
- Frontend UI (PetScanner.jsx):
  * Drag-and-drop uploader + Sample pet selector (Dog, Cat, Parrot, Rabbit).
  * Animated progress scanning bar with step indicators.
  * Non-pet image validation handler returning structured error alerts.
  * Direct action buttons to list pet on market or view similar pets.

4. PET E-COMMERCE & INTERACTIVE CREATION ENGINE
================================================================================
WHAT IT DOES:
Allows users to list their pets for sale or adoption and enables other users to 
search, view details, wishlist, and purchase listed pets. Includes a live preview wizard.

HOW IT WORKS (TECHNICAL EXECUTION):
- Data Model: Defined in backend/Models/petModel.js (PetOrder).
  Fields: category, type, breed, age, price, description, owner (ref User), 
  buyer (ref User), image ({ id, url }), isVerified (Boolean), isApproved (Boolean), 
  soldBool (Boolean).
- Multi-Step Interactive Listing Wizard (SellPets.jsx, StepProgress.jsx, PetProfilePreviewCard.jsx):
  * Step 1: Category & Breed selection.
  * Step 2: Details (Age, Gender, Price, Location, Description).
  * Step 3: Images & Live Interactive Card Preview (PetProfilePreviewCard.jsx).
- Admin Verification Flow:
  1. Admins fetch pending listings via GET /api/admin/get-pet-list.
  2. Approving via POST /api/admin/approve-pet sets isApproved: true and isVerified: true.
- Marketplace Browsing & Purchasing:
  1. Users query GET /api/user/buy-pet to view verified, unsold listings.
  2. Buying a pet via POST /api/user/book-pet sets soldBool: true and updates buyer.
- Wishlist Engine: POST /api/user/wishlist/toggle bookmarks pets in user document (Wishlist.jsx).

5. CARETAKER ONBOARDING & VERIFICATION SYSTEM
================================================================================
WHAT IT DOES:
Allows standard user account holders to apply for upgrading their role to a 
verified caretaker.

HOW IT WORKS (TECHNICAL EXECUTION):
- Data Model: backend/Models/caretakerApplicationModel.js.
  Fields: applicant (ref User), fullName, mobile, experience, skills, availability, 
  hourlyRate, description, status (pending, approved, rejected), isApproved, isVerified.
- Application Submission: POST /api/caretaker/apply.
- Admin Approval:
  1. Admin reviews applications at GET /api/admin/get-caretaker-list.
  2. POST /api/admin/approve-caretaker sets status to approved, updates User role 
     to "caretaker", and initializes an empty CaretakerProfile model.

6. PROFESSIONAL CARETAKER SHOWCASE & VERSIONING ENGINE
================================================================================
WHAT IT DOES:
Provides caretakers with a rich, multi-section showcase (services, rates, home 
environment, trust badges, gallery, availability calendar, safety info) and protects 
platform quality through an Admin Draft Approval & Version Archiving flow.

HOW IT WORKS (TECHNICAL EXECUTION):
- Data Model: backend/Models/caretakerProfileModel.js.
  Tracks: version, status (pending, approved, rejected, archived), headline, 
  profileImage, coverBanner, services, baseDailyRate, additionalPetRate, holidayRate, 
  availabilityDays, operatingHours, gallery, homeEnvironment, safetyInfo, rejectionReason.
- Draft Creation Flow:
  Updating profile via POST /api/caretaker/professional-profile creates a pending 
  draft version (version = currentVersion + 1, status = "pending"). The live 
  profile stays active until draft approval.
- Admin Side-by-Side Approval Flow:
  1. Admins fetch drafts via GET /api/admin/caretaker-profiles/pending.
  2. Admin portal renders side-by-side comparison (AdminProfileReview.jsx).
  3. POST /api/admin/caretaker-profiles/approve archives old profile and promotes draft.
  4. POST /api/admin/caretaker-profiles/reject sets draft status to rejected with reason.

7. REAL-TIME CONNECTION REQUESTS & SOCKET.IO MESSAGING SYSTEM
================================================================================
WHAT IT DOES:
Facilitates connection building between pet owners and caretakers. Once accepted, 
a 1-on-1 real-time chat room is unlocked featuring instant messaging, file uploads, 
read receipts, typing indicators, and online/offline status.

HOW IT WORKS (TECHNICAL EXECUTION):
- Data Models:
  * ConnectionRequest (connectionRequestModel.js): requester, recipient, status, message.
  * Conversation (conversationModel.js): participants, lastMessage, updatedAt.
  * Message (messageModel.js): conversationId, sender, text, image, readBy, createdAt.
- Connection Handshake:
  1. POST /api/chat/requests sends a connection request.
  2. PATCH /api/chat/requests/:id/respond accepts request and creates a Conversation.
- Real-Time WebSocket Architecture (backend/socket.js):
  * Socket Authentication: Validates JWT token on connection handshake.
  * Personal Socket Room: Users join personal room (socket.join(socket.user.id)).
  * Conversation Rooms: Joining chat joins room conversationId.
  * Socket Events: send_message, typing, stop_typing, mark_as_read, user_online/offline.
- Media Messaging: POST /api/chat/messages accepts text + image via Multer/Cloudinary.

8. REAL-TIME NOTIFICATION SYSTEM & UNREAD COUNTERS
================================================================================
WHAT IT DOES:
Keeps users instantly notified about connection requests, application approvals, 
messages, AI scan results, and booking updates. Displays persistent unread badges 
on the Navbar that clear dynamically when read.

HOW IT WORKS (TECHNICAL EXECUTION):
- Data Model: backend/Models/notificationModel.js.
  Fields: user, sender, type, title, message, conversationId, read.
- Real-Time Triggering: Saved to MongoDB and pushed instantly over Socket.io:
  io.to(recipientId).emit("notification", notificationDoc)
- Dynamic Un-Badging: Opening chat room triggers mark_as_read via WebSockets, 
  clearing badges across the frontend instantly.

9. ADMIN SUPERVISION & PLATFORM CONTROL PANEL
================================================================================
WHAT IT DOES:
Equips platform administrators with oversight tools to maintain platform quality, 
verify listings, audit caretakers, and monitor transactions.

HOW IT WORKS (TECHNICAL EXECUTION):
- Admin Authentication: Dedicated route /api/admin/login seeded via adminSeeder.js.
- Control Features:
  * User Directory: View all users, roles, registration dates (GET /api/admin/display-users).
  * Pet Moderation: Approve/reject pet listings (GET /api/admin/get-pet-list, POST /api/admin/approve-pet).
  * Caretaker Verification: Review role applications (GET /api/admin/get-caretaker-list, POST /api/admin/approve-caretaker).
  * Profile Draft Review: Side-by-side version comparison (GET /api/admin/caretaker-profiles/pending).

10. MIDDLEWARE, SECURITY & RATE LIMITING INFRASTRUCTURE
================================================================================
WHAT IT DOES:
Protects backend API endpoints from brute-force spam, unauthenticated access, and memory overflows.

HOW IT WORKS (TECHNICAL EXECUTION):
- aiRateLimiter.js: Uses express-rate-limit to cap guest AI scans at 5 per 15 minutes.
- multer.js: In-memory buffer upload middleware with file type and size restrictions.
- Auth Guards: isAuth.js, caretakerIsAuth.js, isAdmin.js, authenticate.js enforcing JWT security.
