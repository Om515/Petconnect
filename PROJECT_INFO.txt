1. PROJECT OVERVIEW
================================================================================
- Project Name: PetConnect
- Architecture: MERN Stack Monorepo (MongoDB, Express, React, Node.js)
- Goal: Full-stack web application connecting Pet Owners (Users), Pet Caretakers, 
  and Platform Administrators.
- Core Modules:
  1. Pet Marketplace (List pets for sale, browse, buy, verify listings)
  2. Caretaker Services (Apply to be a caretaker, set hourly rate/skills, 
     accept/reject service bookings)
  3. Administrative Platform (User management, caretaker approval, pet verification,
     dashboard metrics)

================================================================================
2. TECH STACK & CONFIGURATION
================================================================================
Backend:
- Node.js (ES Module system "type": "module")
- Express.js v4.21.2
- Database: MongoDB with Mongoose ORM v8.13.0
- Auth: JWT (jsonwebtoken v9.0.2) + Passwords hashed with bcrypt v5.1.1
- Middlewares: cookie-parser, body-parser, cors
- Media Uploads: Multer + DataURI + Cloudinary v2.6.0
- Server Entry: server.js
- Default Port: 7001 (or process.env.PORT)

Frontend:
- React 18 SPA (Single Page Application)
- Vite Build System
- Routing: react-router-dom v6
- State Management: React Context API (AuthContext, AdminContext)
- Styling: Tailwind CSS + Vanilla CSS
- Entry Point: src/main.jsx & src/App.jsx

4. DATABASE SCHEMAS (MONGOOSE MODELS)
================================================================================
1. User Schema (userModel.js):
   - name: String (Required)
   - email: String (Required, Unique)
   - password: String (Required, Hashed)
   - mobile: String (Required, Unique)
   - address: String (Required)
   - role: String (Enum: ["user", "caretaker", "admin"], Default: "user")
   - timestamps: true

2. Caretaker Application Schema (caretakerApplicationModel.js):
   - applicant: ObjectId ref user (Required)
   - fullName: String (Required)
   - mobile: String (Required)
   - experience: Number (Years)
   - skills: [String] (e.g., ["Dog Walking", "Grooming"])
   - availability: String (Full-time / Part-time)
   - hourlyRate: Number (Required)
   - description: String (Required)
   - status: String (Enum: ["pending", "approved", "rejected"], Default: "pending")
   - isApproved: Boolean
   - isVerified: Boolean

3. Pet / PetOrder Schema (petModel.js):
   - category: String (Required)
   - type: String (Required)
   - breed: String (Required)
   - age: Number (Required)
   - price: Number (Required)
   - description: String (Required)
   - owner: ObjectId ref user (Required)
   - image: { id: String, url: String } (Cloudinary)
   - isVerified: Boolean (Default: false)
   - isApproved: Boolean (Default: false)
   - soldBool: Boolean (Default: false)
   - buyer: ObjectId ref user

4. Booking Request Schema (bookingRequestModel.js):
   - user: ObjectId ref user (Pet Owner)
   - caretaker: ObjectId ref user (Caretaker)
   - service: String (Required)
   - date: Date (Required)
   - hours: Number (Required)
   - totalCost: Number (Required)
   - status: String (Enum: ["pending", "accepted", "rejected"], Default: "pending")

5. Admin Schema (adminModel.js):
   - name: String
   - email: String (Unique)
   - password: String
   - role: String ("admin")

5. API ROUTES MAP
================================================================================
Auth Routes (/api/auth):
- POST /api/auth/register : Register new user
- POST /api/auth/login    : Authenticate user/caretaker/admin
- GET  /api/auth/me       : Fetch logged-in user profile & role status
- POST /api/auth/logout   : Clear session / cookies

User Routes (/api/user):
- GET  /api/user/profile       : Get user profile
- PUT  /api/user/profile       : Update user profile
- POST /api/user/sell-pet      : Post a pet listing with image
- GET  /api/user/pets          : Browse available pets
- GET  /api/user/pet/:id       : Get pet detail
- POST /api/user/buy-pet/:id   : Buy a pet
- GET  /api/user/caretakers    : List approved caretakers
- POST /api/user/book-caretaker: Book caretaker service
- GET  /api/user/my-bookings   : View booking history

Caretaker Routes (/api/caretaker):
- POST /api/caretaker/apply            : Submit application
- GET  /api/caretaker/profile          : Get caretaker details
- PUT  /api/caretaker/profile          : Update rates & availability
- GET  /api/caretaker/bookings         : View booking requests
- PUT  /api/caretaker/booking/:id/status: Accept/reject booking

Admin Routes (/api/admin):
- POST /api/admin/login                     : Admin authentication
- GET  /api/admin/users                     : List registered users
- DELETE /api/admin/user/:id                : Delete user
- GET  /api/admin/caretaker-applications    : View caretaker applications
- PUT  /api/admin/caretaker-application/:id/approve: Approve caretaker
- PUT  /api/admin/caretaker-application/:id/reject : Reject caretaker
- GET  /api/admin/pets                      : View all pets
- PUT  /api/admin/pet/:id/verify            : Approve/verify pet listing
